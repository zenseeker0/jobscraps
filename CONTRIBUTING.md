# Contributing to Jobscraps

Thank you for helping improve Jobscraps! This document describes our Git branching model, PR process, and cleanup guidelines so everyone’s contributions stay consistent, traceable, and easy to manage.

---

## 🏷 Branch Naming Conventions

We use four branch types:

1. **`main`**  
   The protected default branch. All releases live here.

2. **`feature/<subfeature-name>`**  
   Your day-to-day work on a small piece of a larger feature.

3. **`codex/<short-desc>-YYYYMMDD`**  
   Ephemeral “scratch-pad” branches generated by ChatGPT Codex.  
   *Never* rename these—Codex expects the exact branch name.

4. **`feature/umbrella-feature`**  
   An aggregation branch (e.g. `feature/modular-refactor`) that pulls in multiple `feature/…` sub-branches before final merge to `main`.

> **Example branch names:**  
> `feature/modular-refactor-create-config-files`  
> `codex/separate-cli-20250622`  
> `feature/modular-refactor`

---

## 🚀 Workflow

1. **Create your Feature sub-branch**  
   ```bash
   git checkout -b feature/<subfeature-name>
   git push -u origin feature/<subfeature-name>

This ensures Codex and teammates can see and target your branch.
	2.	Invoke Codex on that branch
Ask Codex to “create branch codex/<short-desc>-YYYYMMDD from feature/<subfeature-name> and implement X.”
	•	Let Codex commit and open a PR from codex/… → your feature/….
	•	Do not rename the codex/… branch.
	3.	Merge “codex” work into your Feature
	•	Review the PR (codex/… → feature/…).
	•	Merge once approved.
	•	Delete the codex/… branch both locally and remotely:

git branch -D codex/<short-desc>-YYYYMMDD
git push origin --delete codex/<short-desc>-YYYYMMDD


	4.	When your sub-feature is complete, open a PR:

codex work → feature/<subfeature-name> → feature/umbrella-feature

Merge, then delete the now-merged sub-feature:

git branch -d feature/<subfeature-name>
git push origin --delete feature/<subfeature-name>


	5.	Finalize umbrella Feature
	•	Once all sub-features are in, open PR:
feature/umbrella-feature → main
	•	Merge and delete:

git branch -d feature/umbrella-feature
git push origin --delete feature/umbrella-feature


	6.	Keep main clean
	•	Always work via PRs; never push directly to main.
	•	Enable branch protection on GitHub to require reviews and passing CI.

⸻

📋 Pull Request Guidelines
	•	Title:
[<branch-type>] Short, imperative description
e.g. [feature] Add JSON config loader
	•	Description:
	•	Explain why and what changed.
	•	Link any related issues or tickets.
	•	List manual steps to verify.
	•	Reviews & Checks:
	•	At least one approving review.
	•	All CI checks (lint, tests) must pass.

⸻

📝 Commit Message Style
	•	Use the imperative mood: “Add X,” “Fix Y,” “Remove Z.”
	•	Optionally prefix with type: feat:, fix:, chore:, etc.
	•	Keep the subject line ≤ 50 chars and body wrapped at 72 chars.

⸻

🔧 Code Quality
	•	Linting: Run flake8 (Python) or your project’s linter before PR.
	•	Formatting: Stick to our style (e.g. use Black or Prettier).
	•	Tests: Add or update tests for new behavior.

⸻

📦 Cleanup Checklist
	•	Delete all codex/… branches after merge.
	•	Delete feature sub-branches after merging into umbrella.
	•	Prune remote-tracking refs:

git fetch --prune


	•	Keep your local git status clean and working tree tidy.

⸻

Thanks for contributing! With this model, you’ll get predictable history, minimal branch clutter, and a smooth handoff between Codex, feature work, and release. If you have any questions or improvements to this guide, please open an issue or PR against main.
